Frame Analyzer documentation

This app runs modal, pushover and time-history analyses of 2D and 3D moment frames entirely in the web browser. It is the HTML + CSS + JavaScript version of the OpenSeesPy / Streamlit Frame Analyzer. It has the same inputs, the same model and the same outputs, but needs no Python, no installation and no server.

1. Overview

The app has two parts:

  • A user interface (index.html, css/style.css, js/app.js, js/plots.js). You define the frame, run analyses and view and download the results.
  • A finite element engine written in JavaScript (js/engine.js and the modules it uses). It re-implements the parts of OpenSees the frame model needs: force-based, displacement-based and elastic beam-columns, fiber sections, the uniaxial material models, Linear/P-Delta transformations, rigid diaphragms, zero-length joint springs, Newton-type solvers, displacement control, Newmark integration, Rayleigh damping and eigenvalue analysis.

The engine follows the OpenSees formulations closely. The test suite in section 9 compares it with OpenSeesPy, and for most models periods, pushover curves and time histories agree to machine precision.

Features

  • 2D frames (X–Y plane) and 3D frames (X–Y plan, Z vertical), 1–30 stories, 1–20 bays in each direction.
  • Element types: forceBeamColumn, dispBeamColumn, elasticBeamColumn; Lobatto, Legendre, Radau and Newton-Cotes integration with 2–10 points.
  • Sections: RC rectangle (fiber, confined core + cover + bars), steel I-section (fiber), elastic rectangle.
  • 13 uniaxial materials, plus a Custom entry that takes OpenSees-style arguments.
  • Rigid, pinned or semi-rigid beam–column joints (any spring material; stiffness given as k or as a fixity factor γ).
  • Rigid floor diaphragms, P-Delta for columns, gravity loads with automatic seismic mass.
  • Modal analysis with participation factors and mass ratios; pushover (triangular, uniform or first-mode pattern); time history using an uploaded record (PEER AT2, single column, time–acc), a synthetic record or a sine wave.
  • Interactive SVG charts with hover read-out. 3D drawings rotate when dragged. Results download as CSV.
  • Engine messages, a likely cause and a JavaScript stack trace are shown when an analysis fails.
  • Works offline from a local folder (file://), with light and dark themes and a phone-width layout.

Requirements

Any current desktop or mobile browser (Chrome, Edge, Firefox or Safari from 2022 or later). Nothing to install and no internet connection needed: the app uses no external libraries, fonts or CDNs.

2. Quick start

  1. Open web/index.html in your browser (double-click it), or serve the web folder from any static web server.
  2. The default model (3-story, 2-bay RC frame with fiber sections) is built and its gravity analysis runs at once. The Model tab shows the frame, the section properties and the cross-sections.
  3. Change any input in the left-hand Model panel. About half a second after you stop typing, the model is rebuilt and gravity re-run.
  4. Open Modal and press Run modal analysis to get periods, mass participation and mode shapes.
  5. Open Pushover, choose the load pattern and target drift, then press Run pushover. A progress bar appears, and Stop ends the run early but keeps the results so far.
  6. Open Time history, pick or upload a ground motion and press Run time history.
  7. Use Download CSV under each result to export the numbers, and Save at the top of the panel to keep the model as a JSON file.
Your inputs are also kept in the browser's local storage, so reloading the page restores the last model. Reset restores the defaults.

Model tab

Shows the frame drawing, a table of section properties (E, A, I, plus I weak and J in 3D, bars, As and ρ), the total seismic weight and height, counts of nodes, columns, beams, joint springs and equations, and the engine messages from the gravity analysis. Below are the column and beam cross-sections, drawn to scale with dimensions: confined core dark grey, cover light grey, bars orange. Pinned joints appear as hollow circles at the beam ends and semi-rigid joints as filled circles. In 3D, drag the drawing to rotate it and double-click to reset the view.

If the model cannot be built, or gravity does not converge, the tab shows the error, a likely cause, the engine messages and the stack trace (see section 8).

Modal tab

Enter the number of modes (up to the number of dynamic degrees of freedom; the help icon shows the maximum) and run. The table lists for each mode: period T, frequency f, circular frequency ω, and for each lateral direction the participation factor Γ, the effective mass ratio and the cumulative mass ratio. Mode shapes are drawn for the first 12 modes. If the tangent stiffness after gravity has negative eigenvalues, a warning explains that the structure is unstable under its own gravity loads.

Pushover tab

Inputs: lateral load pattern (Triangular (inverted) ∝ m·h, Uniform ∝ m, First mode ∝ m·φ of the mode with the largest participation in the chosen direction), direction (X or Y, 3D only), target roof drift (%) and number of steps. The results show the status, the engine messages, the maximum base shear, V/W, the final roof displacement, the pushover curve, the interstory-drift profile at the final step and the deformed shape with an adjustable scale.

Time-history tab

Ground motion, choose one of three sources:

  • Upload record: PEER NGA .AT2 files (NPTS and DT read from the header, old and new formats), single-column files (enter dt) or two-column time–acceleration files. Commas, spaces and semicolons are accepted, and lines starting with # are ignored. Units g, m/s² or cm/s².
  • Synthetic: Kanai–Tajimi filtered white noise (ground frequency fg, damping ζg) with a trapezoidal envelope (quadratic build-up to 10% of the duration, strong motion to 50%, exponential decay), scaled to the PGA. The random seed makes it repeatable.
  • Sine wave: amplitude, period, duration (dt = 0.005 s).

The record preview shows the PGA, dt and number of points. Analysis settings: scale factor, damping ratio ζ, the two modes i, j used for Rayleigh damping, analysis time step, free-vibration time added after the record, and the excitation direction (3D). Results: status, Rayleigh coefficients, peak roof displacement (with its time), peak base shear, V/W, maximum interstory drift, roof displacement and base shear histories, the base-shear–roof-displacement loop and the peak drift profile.

Saving and opening models

Save downloads frame-model.json with every input, including the values entered for each material type. Open loads such a file. Older or hand-edited files work too, because missing fields are filled with the defaults. Results are not stored in the file; re-run the analyses after opening.

5. The structural model

Geometry and numbering

Grid lines are at x = j·bay and (3D) y = k·bay_y. Level 0 is the base; level 1 is at h1 and higher levels are spaced h apart. Node tags follow the Python version: tag = floor·10000 + iy·100 + ix + 1. Rigid-diaphragm master nodes (3D) are 2000000 + floor, at the centre of the plan; auxiliary hinge nodes are numbered from 1000001. Columns are created story by story, followed by beams floor by floor (X beams, then Y beams).

Supports and constraints

  • All base nodes are fully fixed.
  • Rigid diaphragm, 2D: the horizontal displacement of every floor node equals that of the first node of the floor (equalDOF, dof 1).
  • Rigid diaphragm, 3D: each floor has a master node with free ux, uy, rz (uz, rx, ry fixed); the floor nodes follow the rigid in-plane motion of the master (rigidDiaphragm perpendicular to Z): ux = uxm − (y − ym)·rz, uy = uym + (x − xm)·rz, rz = rzm.

The engine imposes constraints exactly, by transformation, like the OpenSees Transformation constraint handler. Each node dof is written as a linear combination of independent unknowns. The masses therefore transform as TᵀMT, so a 3D diaphragm gets the correct rotational inertia. The unknowns are renumbered with reverse Cuthill–McKee to keep the stiffness profile small.

Elements and transformations

ElementFormulation
elasticBeamColumnClosed-form stiffness with E, A, I (and G, J, I weak in 3D) from the section; RC sections use the initial concrete modulus with I and J × the cracked-stiffness factor.
dispBeamColumnCubic Hermite displacement field; section deformations ε = v₀/L, κ = [(6ξ−4)v₁ + (6ξ−2)v₂]/L; stiffness and forces integrated over the integration points; uniform loads as fixed-end forces.
forceBeamColumnFlexibility formulation with exact force interpolation (axial constant, moments linear plus the particular solution of the uniform load). Element state determination as in OpenSees: Newton iterations with the section flexibility, then initial-flexibility iterations, then initial-then-Newton, then subdividing the deformation increment (energy tolerance 10⁻¹², 10 iterations).

Coordinate transformations: Linear for beams and either Linear or PDelta for columns (the P-Delta option). P-Delta adds the geometric stiffness (N/L) in both transverse directions and the matching forces. In 3D the local axes follow OpenSees (y = vecxz × x, z = x × y):

Beam–column connections

For pinned and semi-rigid joints an auxiliary node is created at each beam end, at the same position as the column node. It shares every unknown with the column node except the beam's bending rotation (rz in 2D; ry for X beams and rx for Y beams in 3D). With a pinned joint that rotation is free, so no moment is transferred. With a semi-rigid joint a zero-length rotational spring with the chosen material connects the two rotations. Torsion and weak-axis bending stay continuous. The Python version used stiff penalty springs for the tied dofs; the exact tie here gives the same results without penalty error. As in OpenSees, joint springs are left out of the Rayleigh damping matrix.

Loads and masses

Every beam carries a uniform load in its local −y direction (downwards): w_floor on floors, w_roof on the roof. Each floor's mass is split equally between its grid nodes and assigned to all translational dofs. With From gravity loads the mass per floor is w × L / g, where L is the total beam length of a floor (n_bays·bay in 2D; n_x·bay_x·(n_y+1) + n_y·bay_y·(n_x+1) in 3D).

6. Analyses

Gravity

Every model build applies the beam loads with load control in 10 steps of 0.1, using Newton iterations and a displacement-increment norm test (tolerance 10⁻⁸, 50 iterations). The loads are then held constant and the time is reset to 0, like OpenSees loadConst -time 0. Every analysis starts from this state on a freshly built model.

Modal

Solves K φ = λ M φ with the tangent stiffness after gravity, so P-Delta and any cracking are included. The massless (rotational) dofs are condensed out exactly: the flexibility at the mass dofs is taken from the factorised K, and the reduced symmetric problem LᵀFL ψ = (1/λ) ψ (M = LLᵀ) is solved with Householder tridiagonalisation and implicit QL. Large models asking for few modes use subspace iteration instead. Modes are mass-normalised (φᵀMφ = 1). For each lateral direction d: L = Σ m·φd, Γ = L / Σ m·|φ|², mass ratio = L² / (Σ m·|φ|²) / M_total, summed over the grid-node masses (same as engine.py). The number of modes is limited to the number of mass dofs (2D rigid: ns·(1+nn); 2D flexible: 2·ns·nn; 3D rigid: ns·(3+nn); 3D flexible: 3·ns·nn).

Pushover

Lateral nodal loads in the chosen direction are split equally between the nodes of each floor, with floor weights normalised to sum 1. Displacement control is applied at the roof control node (roof master in 3D rigid, otherwise the first roof node), with increment target/steps (tolerance 10⁻⁶, 100 iterations). If a step fails with every algorithm (see solution algorithms), it is retried as 10 sub-steps; if that also fails, the analysis stops and reports the drift reached. Base shear is the negative sum of the column resisting forces at the base nodes, the same as summing the OpenSees reactions.

Time history

  • Damping: Rayleigh, αM = 2ζωiωj/(ωi+ωj), βK = 2ζ/(ωi+ωj) (or ζω and ζ/ω when i = j), using the committed stiffness, like OpenSees rayleigh(αM, 0, 0, βK). Periods come from an eigen analysis after gravity.
  • Excitation: uniform base acceleration a_g(t) = scale · g · record(t) in the chosen direction, P_eff = −M·r·a_g. The record is interpolated linearly and is zero after its last interval (OpenSees Path series).
  • Integration: Newmark average acceleration (γ = 0.5, β = 0.25), displacement form with the OpenSees predictor; tolerance 10⁻⁸, 50 iterations. A failed step is retried as 10 sub-steps of dt/10; if that fails, the analysis stops and reports the time reached.
  • Duration = record length + free-vibration time; number of steps = round(duration / dt).

Solution algorithms

Each step tries these algorithms in order, returning to the last converged state after each failure. The list follows _try_step in engine.py:

  1. Newton: tangent re-formed every iteration.
  2. ModifiedNewton: tangent from the first iteration of the step.
  3. NewtonLineSearch: interpolated (secant) line search, ratio 0.8.
  4. KrylovNewton: modified Newton with Krylov subspace acceleration (Carlson–Miller, subspace size 3).
  5. Newton with initial stiffness: replaces BFGS from the Python list.

Linear systems use a symmetric skyline (profile) LDLᵀ solver after RCM renumbering; a zero pivot is reported as a singular stiffness matrix with the node and dof. Convergence uses the norm of the displacement increment (OpenSees NormDispIncr).

8. Errors and troubleshooting

When an analysis fails, the app shows the error, a likely cause chosen from the messages, the engine messages (OpenSees-style warnings) and the JavaScript stack trace.

Message containsLikely cause and fix
Invalid #args, invalid type, unknown material, envelope needs…A material definition was rejected: check the parameters; for a Custom material, the name and the number/order of the arguments.
Invalid sectionImpossible section dimensions (e.g. 2·cover ≥ b, d ≤ 2·tf).
eigen analysis, NCV must be greaterMore modes requested than dynamic dofs, or zero mass. Reduce the number of modes or Rayleigh mode j; check masses > 0.
singular, zero pivotMechanism or zero stiffness: check dimensions, E, the connection type and the spring stiffness.
failed to converge, compatible element forcesNonlinear solution did not converge: use a smaller dt or more pushover steps, a lower scale factor or target drift, or try the elastic element first. If the elastic model runs, the cause is material softening (concrete crushing, very low εcu, b = 0 for steel).

Other tips

  • Negative eigenvalues / very long periods: the gravity load exceeds the P-Delta buckling load (for example pinned beams with tall, slender cantilever columns). Use stiffer columns, fixed joints or switch P-Delta off to compare.
  • Brittle concrete tension (Concrete04 with εt ≈ ft/Ec) makes pushover curves jagged; this is real model behaviour and appears in OpenSees too.
  • The page is slow: big 3D fiber models are expensive (see section 11). Use fewer integration points, the dispBeamColumn element or an elastic model while exploring.
  • Inputs reset after reopening the file: some browsers block local storage for file:// pages; use Save/Open.

10. Differences from the Python version

  • No OpenSees needed. The analysis engine is a JavaScript re-implementation; there is no Python, venv or Streamlit server.
  • Exact constraints replace the penalty zero-length springs used at pinned/semi-rigid joints (differences of the order of the 10⁻⁴ penalty ratio).
  • Algorithm list: BFGS is replaced by Newton with the initial stiffness.
  • Eigen solver: exact condensation with a dense symmetric solver (or subspace iteration), so every mode up to the number of mass dofs is available (the ARPACK limit of n − 1 no longer applies).
  • ReinforcingSteel and Concrete07 cyclic rules are simplified (envelopes exact).
  • Custom materials accept only the material types implemented in the engine (listed above), not every OpenSees material.
  • Synthetic records use a different random number generator (and power-of-two FFT), so the same seed gives a different (statistically equivalent) record from the Python version.
  • Drift profiles are drawn as true story profiles (each story's drift spans that story).
  • Additions: Stop button with partial results, save/open model files, inputs remembered in the browser, rotatable 3D drawings, chart hover read-out, dark mode, negative-eigenvalue warning, and Synthetic as the default ground motion (so the tab works without a file).

11. Performance and limits

Run times depend on the number of fibers × integration points × elements. 2D models and elastic 3D models are fast (well under a second per pushover). A 3D RC fiber model has about 360 fibers per section, the same discretisation as the Python model. A 5-story 3 × 3-bay force-based RC model takes a few seconds to build and run gravity, and a pushover takes proportionally longer. Analyses run in short slices, so the page stays responsive and the Stop button works. For big models:

  • use dispBeamColumn with 3 Legendre points, or fewer integration points;
  • explore with elasticBeamColumn first;
  • use fewer pushover steps or a larger time step where the response allows it.

Memory grows with the number of fibers (each fiber stores its own material state). The input limits match the Python version (30 stories, 20 × 20 bays), but the largest 3D fiber models are better run in OpenSees itself.

13. Scripting the engine

The engine has no dependency on the interface. Load the first six scripts on any page (or open the browser console on index.html) and call it directly. Parameters use the same keys as build_model in engine.py:

const M = FA.materials, E = FA.engine;
const rc = (b, h) => ({
  kind: 'RC rectangle (fiber)', b, h, cover: 40, d_bar: 20, n_top: 3, n_bot: 3, n_side: 0,
  conc: M.defaultSpec('Concrete02', 'concrete'), K: 1.2, epscu_core: 0.015, crack: 0.5,
  steel: M.defaultSpec('Steel02', 'steel'),
});
const p = {
  dim: 2, n_stories: 3, n_bays: 2, bay: 5, n_bays_y: 0, bay_y: 5, h1: 3.5, h: 3.0,
  rigid_diaphragm: true, pdelta: true, ele_type: 'forceBeamColumn', n_ip: 5, integ: 'Lobatto',
  col_sec: rc(400, 400), beam_sec: rc(300, 500), conn: { type: 'Rigid' },
  w_floor: 25, w_roof: 20, m_floor: 25 * 10 / 9.81, m_roof: 20 * 10 / 9.81,
};

let info = E.buildModel(p);                       // model + gravity
const modes = E.runModal(info, 3);
console.log(modes.map(m => m.T));                 // [0.3494, 0.1092, 0.0627]

info = E.buildModel(p);                           // fresh model for each analysis
const po = await E.runPushover(info, 'Triangular (inverted)', 3.0, 200, 1,
  { progress: f => console.log(f), cancelled: () => false });
console.log(Math.max(...po.V), po.status);

info = E.buildModel(p);
const [acc, dt] = FA.records.sineRecord(0.3, 0.6, 5, 0.005);
const th = await E.runTimeHistory(info, acc, dt, 1.0, 0.05, 0.01, 1.0, [1, 3], 1);
console.log(Math.max(...th.roof.map(Math.abs)));
console.log(info.domain.logText());              // engine messages

Returned objects mirror the Python dictionaries: runModal → list of modes with T, f, omega, gamma_x, ratio_x, cum_x, shape; runPushover → {roof, V, floors, drifts, H, W, status, final}; runTimeHistory → {t, roof, V, floors, drifts, status, rayleigh, periods, W}. Lower-level objects (info.domain, its nodeDisp(tag, dof), eigen(n), elements and materials) are also available.

14. Extending

Adding a material

  1. In materials.js part 1, write a class with setTrial(strain) (sets sig, tan from the committed state), commit(), revert() and an E0 property.
  2. Add a case for its OpenSees name in uniaxial(name, args) that checks the arguments and returns a function creating new instances, and add the name to IMPLEMENTED.
  3. To offer it in the forms, add an entry to LIST in part 2 with its families, parameters (name, label, kind, defaults per family), the argument builder args(v, scale), E0(v) and, for concrete, an optional confine function. The form, model files and Custom material pick it up automatically.

Adding a section type

Extend sectionProps and sectionMaker in sections.js, the section form in app.js (sectionInputs, secSpec) and the drawing in plots.section.

Regression testing

The validation in section 9 builds the same parameter dictionaries in Python and JavaScript, runs engine.py with OpenSeesPy and the JavaScript engine in a headless browser, and compares periods, mass ratios, pushover curves, time histories and material stress histories. Repeat this comparison after any change to the engine.
